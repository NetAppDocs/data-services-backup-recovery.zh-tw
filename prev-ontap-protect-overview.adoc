= 使用 NetApp Backup and Recovery 保護 ONTAP Volume 工作負載
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
使用 NetApp Backup and Recovery 來保護和還原您的 ONTAP Volume 資料，並長期歸檔備份。您可以實作 3-2-1 策略，即在兩個不同的儲存設備系統上保留三份來源資料複本，並在雲端保留一份複本。

為系統啟用保護後，Backup and Recovery 會建立 Volume 的區塊層級、永久遞增複本。除了來源 Volume 之外，您還有：

* 來源系統上 Volume 的快照
* 位於不同 ONTAP 儲存系統上的複寫 Volume
* 物件儲存中 Volume 的備份


image:diagram-321-overview-unified.png["圖表顯示備份檔案如何在來源系統中以快照形式存在，在次要儲存設備系統中以複寫的 Volume 形式存在，以及在物件儲存中以備份檔案形式存在。"]

3-2-1 方法有以下優點：

* 多個資料副本可防止內部和外部網路安全威脅。
* 如果一種媒體發生故障，使用不同類型的媒體可以幫助您恢復。
* 您可以從現場副本快速恢復，如果現場副本受到損害，則可以使用異地副本。


必要時，您可以將整個 _Volume_ 、 _資料夾_ 或一或多個 _檔案_ ，從任何複本還原到相同或不同的系統。



[[how-protection-for-ontap-volumes-works]]
== ONTAP Volume 保護的運作方式

當您為 Cloud Volumes ONTAP 或內部部署 ONTAP 系統啟用備份與恢復時，該服務會執行 Volume 資料的完整基礎傳輸。之後，所有傳輸均為遞增：僅傳輸已變更和新增的區塊，從而將網路流量保持在最低限度。

備份與恢復使用 ONTAP SnapMirror 技術來保持您的複本同步。它會在來源 Volume 上建立快照，並將其傳輸至複寫與備份位置。備份至物件儲存是建置於 https://docs.netapp.com/us-en/ontap/concepts/snapmirror-cloud-backups-object-store-concept.html["NetApp SnapMirror雲端技術"^]之上。

image:diagram-backup-recovery-general.png["此圖顯示了NetApp Backup and Recovery系統和目標物件儲存進行通訊。"]

此圖顯示將 Volume 複寫到 Cloud Volumes ONTAP 系統，但您也可以將 Volume 複寫到內部部署的 ONTAP 系統。

每種類型的複本都位於不同的位置：

* 快照儲存在來源系統的來源磁碟區上。
* _複寫的 Volume_ 位於次要儲存設備系統上，該系統可以是 Cloud Volumes ONTAP 或內部部署 ONTAP 系統。
* _備份複本_ 位於雲端帳戶或內部部署的物件存放區中。控制台會為每個叢集建立一個物件存放區。有關控制台如何建立與命名物件存放區的詳細資料，請參閱 link:concept-backup-to-cloud.html#where-backups-reside-in-object-store-locations["備份在物件儲存位置的位置"]。



CAUTION: 請勿直接從您的儲存系統或雲端供應商環境中管理或變更備份檔案。這樣做可能會毀損檔案，並導致不受支援的組態。

若要規劃要使用的複本和架構，請參閱link:prev-ontap-protect-journey.html["規劃 ONTAP Volume 保護"]。



[[features]]
== 特徵

*複製*

* 在ONTAP儲存系統之間複製資料以支援備份和災難復原。
* 一次將多個FlexVol磁碟區複製到輔助系統。
* 在兩個系統之間使用原生 ONTAP 傳輸中加密與預先共用金鑰 (PSK)。
* 在發生傳輸故障的事件時，依靠自我修復複寫。
* 將複寫的 Volume 還原至來源系統或其他系統。


對於 https://docs.netapp.com/us-en/data-services-replication/index.html["NetApp Replication"^] 中在使用 Backup and Recovery 複寫時無法使用的功能，請參閱link:br-reference-limitations.html#replication-limitations-for-ontap-volumes["ONTAP磁碟區的複製限制"]。

*備份到物件儲存*

* 將 Volume 的獨立複本備份到低成本物件儲存，從內部部署或雲端系統備份到公有雲或私有雲。
* 將單一備份原則套用至叢集中的所有 Volume，為具有獨特恢復點目標的 Volume 指派不同的原則，或建立適用於叢集中所有未來 Volume 的原則。請參閱 link:prev-ontap-policy-manage.html["管理 ONTAP Volume 的原則"]。
* 透過 DataLock 和勒索軟體掃描來保護備份免遭刪除和勒索軟體攻擊。請參閱 link:prev-ontap-policy-object-options.html#datalock-and-ransomware-protection-options["DataLock 和勒索軟體保護選項"]。
* 將較舊的備份分層儲存到歸檔儲存設備中，以節省成本。請參閱link:prev-ontap-policy-object-options.html#archival-storage-options["檔案存儲選項"]。
* 刪除備份關係，以便您可以停用來源 Volume，同時保留其備份。
* 單一 Volume 最多可保留 4,000 個備份。
* 使用 AES-256 位元加密保護靜態備份資料，並在傳輸過程中使用 TLS 1.2 HTTPS 連線，或使用您自己的客戶管理金鑰來取代預設的雲端供應商金鑰。


*還原*

* 從本機快照、複寫的 Volume 或物件儲存中的備份還原特定時間點的資料。
* 將 Volume、資料夾或單一檔案還原到來源系統或不同的系統，包括使用不同訂閱或帳戶的系統，或位於不同區域的系統。
* 當您需要盡快提供對 Volume 的存取時（例如在災難恢復情況下），請將 Volume 從物件儲存 _快速還原_ 至 Cloud Volumes ONTAP 或內部部署系統。
* 將資料按區塊層級直接還原到您指定的位置，並保留原始 ACL。
* 瀏覽或搜尋檔案目錄，選擇要還原的單一資料夾和檔案。


請參閱link:prev-ontap-restore.html["恢復ONTAP磁碟區工作負載"]以了解還原選項。



[[supported-volumes]]
== 支持的捲

NetApp Backup and Recovery支援以下類型的磁碟區：

* FlexVol讀寫卷
* FlexGroup磁碟區（需要ONTAP 9.12.1 或更高版本）
* SnapLock Enterprise磁碟區（需要ONTAP 9.11.1 或更高版本）
* SnapLock Compliance 適用於內部部署 Volume（需要 ONTAP 9.14 或更新版本）
* SnapMirror資料保護 (DP) 目標卷



NOTE: NetApp Backup and Recovery不支援FlexCache磁碟區的備份。

有關 Backup and Recovery 支援的來源系統、二線系統、物件儲存目的地、還原目的地和區域，請參閱 link:br-start-sources-destinations.html["NetApp Backup and Recovery 中支援的備份與恢復目的地"]。有關其他需求和限制，請參閱 link:br-reference-limitations.html["NetApp Backup and Recovery for ONTAP磁碟區的已知限制"]。



[[cost-and-licensing]]
== 成本與授權

建立快照或複寫 Volume 無需支付任何費用，只需支付它們佔用的磁碟空間即可。雲端供應商的資源費用和 NetApp 的服務費用僅適用於備份到物件儲存。

如需費用與授權選項的詳細資訊，請參閱 link:concept-backup-to-cloud.html#cost["了解NetApp Backup and Recovery"] 和 link:br-start-licensing.html["設定授權"]。
