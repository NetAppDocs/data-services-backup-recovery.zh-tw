[role="lead"]
NetApp Backup and Recovery 支援 Azure 存檔存取分層，可用於對較舊的備份進行分層，從而降低儲存設備成本。存檔備份的還原成本更高，所需時間也更長，因此在對備份進行分層之前，請審查還原成本和擷取時間。



[[supported-azure-blob-access-tiers-for-netapp-backup-and-recovery]]
== NetApp Backup and Recovery支援的 Azure Blob 存取層

備份檔案最初建立時，會儲存在「冷存取分層」。該分層針對儲存不經常存取的資料進行了最佳化，但需要時可以立即存取。

如果您的來源叢集執行的是 ONTAP 9.10.1 或更高版本，您可以選擇在特定天數（通常超過 30 天）後將備份從 _Cool_ 分層到 _Azure Archive_ 儲存設備，以進一步最佳化成本。此分層中的資料無法在需要時立即存取，並且需要較高的擷取成本，因此您需要考慮從這些歸檔備份檔案中還原資料的頻率。請參閱此頁面上有關從歸檔儲存設備還原資料的區段。

當您使用這種類型的生命週期規則設定 NetApp Backup and Recovery 時，在您的 Azure 帳戶中設定 Container 時，請勿設定任何生命週期規則。

https://docs.microsoft.com/en-us/azure/storage/blobs/access-tiers-overview["了解 Azure Blob 存取層"^]。



[[restore-data-from-archival-storage]]
== 從檔案儲存中復原數據

雖然將較舊的備份檔案儲存在歸檔儲存設備中比儲存在冷儲存設備中便宜得多，但從 Azure 歸檔中的備份檔案存取資料以進行還原作業需要更長時間且成本更高。

從 Azure 存檔復原資料需要多少費用？:: 從 Azure 檔案擷取資料時，可以選擇兩個還原優先權：
+
--
* *高*：檢索速度最快，成本較高
* *標準*：檢索速度較慢，成本較低


每種方法都有不同的每 GB 檢索費用和每個請求費用。有關 Azure 區域 Azure 存檔定價的詳細信息，請訪問 https://azure.microsoft.com/en-us/pricing/details/storage/blobs/["Azure 定價頁面"^]。

--



NOTE: 從 Azure 還原資料到 StorageGRID 系統時，不支援高優先權。

恢復 Azure 存檔中存檔的資料需要多長時間？:: 還原時間由兩部分組成：
+
--
* *檢索時間*：從 Azure 檔案中擷取已存檔的備份檔案並將其放置在冷儲存中的時間。這有時被稱為“補水”時間。檢索時間根據您選擇的復原優先順序而不同：
+
** *高*：< 1 小時
** *標準*：< 15 小時


* *恢復時間*：從冷儲存中的備份檔案還原資料的時間。這次與不使用存檔層時直接從冷儲存進行的典型復原作業沒有什麼不同。
+
有關 Azure 存檔檢索選項的更多信息，請參閱 https://azure.microsoft.com/en-us/pricing/details/storage/blobs/#faq["此 Azure 常見問題解答"^]。



--


[NOTE]
====
從歸檔儲存設備還原 Volume 或檔案可能需要額外時間。在備份與還原功能根據所選優先順序重試還原期間，作業監視器中該作業將保持「進行中」狀態。請在「作業監視器」中監視還原；當所有重試嘗試後，作業達到最終狀態（例如「已完成」或「失敗」）時，還原才會完成。除非作業最終失敗，否則請勿啟動另一次還原。
