= 使用 NetApp Backup and Recovery 還原 Oracle 資料庫工作負載
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
使用 NetApp Backup and Recovery，從 Snapshot 快照技術、次要儲存設備上的複寫備份或儲存在物件儲存中的備份還原 Oracle 資料庫工作負載。

.從這些位置恢復
您可以從不同的起始位置還原資料庫：

* 從主位置還原（本地快照）
* 從二級儲存上的複製資源恢復
* 從物件儲存備份還原


.恢復到這些點
您可以將資料庫還原到原始位置，或將其還原為另一個已註冊主機（備用位置）上的新資料庫。

* 恢復到原始位置
* 還原到備用位置（不同的註冊主機）




[[how-oracle-database-restore-works]]
== Oracle 資料庫還原的工作原理

還原 Oracle 資料庫工作負載時，會發生以下情況：

* 當您從本機快照還原資料庫時， NetApp Backup and Recovery會使用備份中的資料建立_新_資源。
* 從複製的儲存空間還原時，您可以將其恢復到原始位置。
* 當您還原至替代位置時， NetApp Backup and Recovery 會將來源資料庫的選定備份還原為不同已註冊主機上的新資料庫。您指定目標主機和新資料庫的名稱。如果您未提供還原規格檔案， Backup and Recovery 會自動計算目標主機上資料檔案、控制檔案和重做日誌檔的位置。
* 從物件儲存還原備份時，您可以將資料還原到來源儲存或本機ONTAP系統，然後從那裡還原資料庫。




[[view-information-about-available-oracle-database-restore-points]]
== 檢視有關可用 Oracle 資料庫還原點的資訊

檢視可用的還原點，包括 SCN 編號和關聯的資料庫版本。


NOTE: 每次使用 `RESETLOGS` 選項開啟資料庫時，Oracle Database 都會建立一個新的資料庫化身。當您審查還原點以及還原至特定 SCN 時，NetApp Backup and Recovery 會列出相關的資料庫化身。

.步驟
. 從 Backup and Recovery 功能表中，選擇 *Inventory*。
. 從NetApp Backup and Recovery選單中，選擇 *復原*。
. 針對 Oracle 資料庫工作負載選擇 *檢視*。
. 選擇“*資料庫*”標籤。
. 選擇您要檢視其還原點的資料庫的 *Actions* image:icon-action.png["操作圖示"] 圖示，然後選擇 *View protection details*。
. 審查可用的還原點，以及與每個還原點關聯的 SCN 編號和資料庫化身。




[[restore-an-oracle-database]]
== 還原 Oracle 資料庫

根據您的需求，您可以將 Oracle 資料庫還原到特定時間點、特定系統變更號碼 （SCN） 或上次正常狀態。您也可以從 Snapshot 快照技術還原資料庫，並跳過自動恢復程序，例如，若您想手動執行恢復。您可以使用資料庫名稱或特定篩選條件搜尋資料庫。

*所需 NetApp Console 角色* 備份與還原超級管理員或備份與還原還原管理員角色 https://docs.netapp.com/us-en/console-setup-admin/reference-iam-predefined-roles.html["了解所有服務的NetApp Console存取角色"^]。

[[alternate-location-support]]
.開始之前
當您還原至替代位置時，請注意下列支援與不支援的還原情境：

*支援的備用位置還原方案*

* 將單一完整的 Oracle 資料庫還原到單一目標主機
* 恢復到特定時間點、特定 SCN 或最新備份
* 當所選恢復點所需的歸檔日誌未包含在備份中時，使用外部歸檔日誌目錄


*不支援的備用位置還原方案*

* 僅表格空間還原，包括還原 PDB 中的表格空間
* 僅 PDB 還原至不同的 Container 資料庫（CDB）
* 從次要儲存設備還原
* 從物件儲存還原


[NOTE]
====
如果需要將 PDB 或表空間還原到特定時間點或 SCN：

* 請僅選擇一個 PDB。時間點恢復與還原多個 PDB 不相容。
* `PDB$SEED` 不能選擇進行時間點恢復。
* 控制檔案還原不能與 PDB 或 PDB 表空間的時間點恢復結合使用。
*  `SYSTEM`、 `SYSAUX` 和  `UNDO` 表空間無法選取。


====
*關於還原 Oracle Data Guard 資料庫的重要說明*

* 在還原之前，請確保資料庫角色是最新的。如果發生切換或容錯移轉，請選取 *主機* 索引標籤，然後先針對該主機選取 *重新整理*。可用的還原選項取決於資料庫目前的角色。
* 如果資料庫目前是備用資料庫，則無論備份時它扮演什麼角色，都無法將其還原到原始位置。請將其還原到其他位置。
* 如果資料庫目前處於備用狀態，則無法還原僅存在於次要儲存設備或物件儲存中的快照。
* 資料庫成為主資料庫後，您可以將資料庫作為備用資料庫時所建立的備份還原到原始位置。



CAUTION: 還原主資料庫不會改變備用資料庫。在時間點或 SCN 還原後，當您使用 `RESETLOGS`開啟主資料庫時，它會啟動新的資料庫化身。如果備用資料庫已經套用超過該時間點的重做，則備用資料庫上的重做套用會因錯誤而停止，且備用資料庫會保持在其先前的狀態。若要恢復保護，請在還原後使用 Oracle 工具重新建立備用資料庫。

.步驟
. 從NetApp Console選單中，選擇「保護」>「備份和復原」。
. 從NetApp Backup and Recovery選單中，選擇 *復原*。
. 從名稱搜尋欄位右側的下拉清單中，選擇 *Oracle*。
. 輸入要還原的資料庫的名稱或篩選要還原的資料庫所在的資料庫主機。
+
出現符合您的搜尋條件的快照清單。

. 選擇要還原的資料庫的“*恢復*”按鈕。
. 選擇恢復選項：
+
[role="tabbed-block"]
====
.恢復到特定時間點
--
.. 選擇*恢復到特定時間點*。
.. 選擇“下一步”。
.. 從下拉式選單中選擇一個日期，然後選擇*搜尋*。
+
顯示最接近指定日期和時間的快照。

.. 如果快照儲存在多個位置，請選擇要使用的來源位置，並新增或審查位置詳細資訊。
.. 選擇“下一步”。


--
.恢復到特定的系統變更號碼 (SCN)
--
.. （選用）參考 <<檢視有關可用 Oracle 資料庫還原點的資訊>> 以查看可用的 SCN 和相關資料庫化身。
.. 選擇*恢復到特定的系統變更號碼 (SCN)*。
.. 選擇“下一步”。
.. 輸入要用作還原點的 SCN，然後選擇*搜尋*。
+
顯示與指定 SCN 最匹配的快照。如果多個資料庫實例與 SCN 匹配，則顯示所有匹配的實例。

.. 如果多個資料庫版本符合搜尋條件，請選擇具有正確版本的快照。
.. 如果快照儲存在多個位置，請選擇要使用的來源位置，並新增或審查位置詳細資訊。
.. 選擇“下一步”。


--
.恢復到最新備份（上次良好狀態）
--
.. 選擇*恢復到最新備份*。
.. 選擇“下一步”。
+
將顯示最新快照。還原作業將使用所有可用的日誌備份還原到上次的良好狀態。

.. 如果快照儲存在多個位置，請選擇要使用的來源位置，並新增或審查位置詳細資訊。
.. 選擇“下一步”。


--
.從快照還原，無需恢復
--
.. 選擇*從沒有恢復的快照中恢復*。
+
選擇此選項意味著資料庫將從快照還原，但會跳過恢復（不會套用日誌備份）。

.. 選擇“下一步”。
+
顯示可用的快照。

.. 從清單中選取快照，然後選取 *Next*。
.. 如果快照儲存在多個位置，請選擇要使用的來源位置，並新增或審查位置詳細資訊。
.. 選擇“下一步”。


--
====
. 選擇恢復目標位置和設定：
+
[role="tabbed-block"]
====
.恢復到原始位置
--
.. 在「目標設定」部分，執行以下操作：
+
... 對於 RAC 資料庫，請選擇要執行還原的 RAC 節點。此選項僅適用於 RAC 資料庫。
... 選擇要還原的內容：
+
**** 選擇「所有資料檔案」以還原整個資料庫或 Container 資料庫 （CDB）。
**** 選擇「可插拔資料庫 (PDBs)」可以從 CDB 還原一個或多個 PDB，而不會影響 Container 中的其他 PDB。然後從清單中選擇 PDB。
**** 選擇「可插拔資料庫 （PDB） 表空間」（對於非 CDB 資料庫，顯示為「表空間」）以還原特定的 PDB 表空間。然後，選擇 PDB 和表空間。


... （可選）啟用「控制檔案」選項，即可同時還原資料庫控制檔。此選項不能用於 PDB 或 PDB 表空間的時間點還原或 SCN 恢復。
... （可選）啟用「如有需要，請變更資料庫狀態以進行還原和恢復」選項，以允許 Backup and Recovery 根據恢復類型管理資料庫狀態。
... 您可以選擇啟用 *強制原地還原* 選項，以便在備份後新增資料檔，或在 LVM 磁碟群組中新增、刪除或重新建立 LUN 時執行原地還原。這會覆寫外部檔案檢查；資料庫恢復將使用您選擇的還原選項繼續進行。
... 如果要將資料庫還原到特定時間點或 SCN，且歸檔日誌不在設定的位置，請在 *指定外部歸檔日誌檔位置* 欄位中指定外部歸檔日誌檔位置。輸入以 `/`開頭的檔案系統路徑或以 `+`開頭的 ASM 磁碟群組。使用文字輸入欄位旁的「加號」和「減號」按鈕新增或移除位置。從快照還原且不進行恢復時，此欄位不會顯示。
... （可選）啟用「恢復後以讀寫模式開啟資料庫或 Container 資料庫」選項，並選擇與還原範圍相符的子選項（從無恢復的快照還原時，這些選項不會顯示）：
+
**** *所有資料檔案*：恢復後以讀寫模式開啟資料庫或 Container 資料庫。
**** *PDB 或 PDB 表空間*：恢復後以讀寫模式開啟可插拔資料庫。
**** *非 CDB 表空間*：恢復後將表空間上線。




.. 在「前置指令碼和後置指令碼」部分，執行以下操作：
+
... *Prescript*：您可以選擇啟用此選項，並輸入在還原作業之前應執行的指令碼的完整路徑以及該指令碼接受的任何參數。
... *後記*：可選地，啟用此選項並輸入應在復原作業後執行的腳本的完整路徑以及該腳本所採用的任何參數。
... 為指令碼選擇一個逾時值。如果指令碼在此時間段內未能執行，還原仍將繼續進行。




--
.恢復至備用位置
--
將資料庫還原為另一台已註冊主機上的新資料庫。開始前請先審查 <<alternate-location-support,支援與不支援的情境>>。

.. 在「目的地設定」部分，輸入以下資訊：
+
... *目標主機*：選擇要建立新資料庫的已註冊主機。
... *目標資料庫*：輸入目標資料庫的名稱。預設情況下，名稱以來源資料庫的名稱開頭，您可以對其進行編輯。
... *自訂目標資料庫參數*：啟用此選項可上傳自訂還原規格檔案以自訂目標資料庫參數。
... *還原規格檔案*：如果您啟用了 *自訂目標資料庫參數* 選項，請提供還原規格檔案，以控制還原的檔案在目標主機上的放置位置。您可以下載預設的還原規格檔案並對其進行自訂，以變更目標資料庫的詳細資料，例如驗證和日誌位置。
+
如果您不提供還原規格檔案，Backup and Recovery 會自動計算資料檔案、控制檔案和重做日誌檔的位置。

... 如果要將資料庫還原到特定時間點或 SCN，且歸檔日誌不在設定的位置，請在 *指定外部歸檔日誌檔位置* 欄位中指定外部歸檔日誌檔位置。輸入以 `/`開頭的檔案系統路徑或以 `+`開頭的 ASM 磁碟群組。使用文字輸入欄位旁的「加號」和「減號」按鈕新增或移除位置。從快照還原且不進行恢復時，此欄位不會顯示。
... （可選）啟用「恢復後以讀寫模式開啟資料庫或 Container 資料庫」選項，並選擇與還原範圍相符的子選項（從無恢復的快照還原時，這些選項不會顯示）：




--
====
. 選擇*恢復*。
+
還原作業完成後，請檢查 *Inventory* 頁面，確認新資料庫已列出。如果資料庫未列出，請重新整理目標主機。
