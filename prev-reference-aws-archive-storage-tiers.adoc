== NetApp Backup and Recovery支援的 S3 歸檔儲存類

備份檔案最初建立時，會儲存在 S3 _Standard_ 儲存設備。此分層針對不經常存取的資料進行最佳化，但仍允許立即存取。30 天後，備份檔案將轉換至 S3 _Standard-Infrequent Access_ 儲存類別，以節省成本。

如果您的來源叢集運行的是ONTAP 9.10.1 或更高版本，您可以選擇在一定天數（通常超過 30 天）後將備份分層到 _S3 Glacier_ 或 _S3 Glacier Deep Archive_ 存儲，以進一步優化成本。您可以將其設定為“0”或 1-999 天。如果將其設為“0”天，則以後不能將其變更為1-999天。

這些分層中的資料無法在需要時立即存取，並且需要更高的擷取成本，因此您需要考慮從這些歸檔備份檔案中還原資料的頻率。請參閱從歸檔儲存設備中還原資料的章節。

* 如果您在啟動NetApp Backup and Recovery時在第一個備份策略中未選擇任何存檔層，那麼 _S3 Glacier_ 將是您未來策略的唯一存檔選項。
* 如果您在第一個備份策略中選擇了“S3 Glacier”，那麼您可以將該叢集的未來備份策略變更為“S3 Glacier Deep Archive”層。
* 如果您在第一個備份策略中選擇“S3 Glacier Deep Archive”，則該層將是該叢集未來備份策略唯一可用的存檔層。


當您使用這種類型的生命週期規則設定 NetApp Backup and Recovery 時，在 AWS 帳戶中設定儲存桶時，請勿設定任何生命週期規則。

== 從檔案儲存中復原數據

雖然將較舊的備份檔案儲存在歸檔儲存設備中比儲存在標準儲存或標準-IA 儲存設備便宜得多，但從歸檔儲存設備中的備份檔案中存取資料以進行還原作業需要更長時間，成本也更高。

從 Amazon S3 Glacier 和 Amazon S3 Glacier Deep Archive 恢復資料需要多少費用？:: 從 Amazon S3 Glacier 擷取資料時，您可以選擇三種還原優先順序；從 Amazon S3 Glacier Deep Archive 擷取資料時，您可以選擇兩種還原優先順序。S3 Glacier Deep Archive 的成本低於 S3 Glacier：
+
--
[cols="25,25,25,25"]
|===
| 存檔層 3+| 恢復優先順序和成本 


|  | *高的* | *標準* | *低的* 


| *S3 冰河* | 檢索速度最快，成本最高 | 檢索速度較慢，成本較低 | 檢索速度最慢，成本最低 


| *S3 Glacier 深度存檔* |  | 檢索速度更快，成本更高 | 檢索速度較慢，成本最低 
|===
每種方法都有不同的每 GB 檢索費用和每個請求費用。有關 AWS 區域 S3 Glacier 的詳細定價，請造訪 https://aws.amazon.com/s3/pricing/["Amazon S3 定價頁面"^]。

--
恢復存檔在 Amazon S3 Glacier 中的物件需要多長時間？:: 總還原時間分為兩部分：
+
--
* *擷取時間*：從歸檔中擷取備份檔案並將其放置到標準儲存設備所需的時間。這有時被稱為「rehydration」時間。擷取時間會根據您選擇的還原優先順序而有所不同。
+
[cols="25,20,20,20"]
|===
| 存檔層 3+| 復原優先權和檢索時間 


|  | *高的* | *標準* | *低的* 


| *S3 冰河* | 3-5分鐘 | 3-5小時 | 5-12小時 


| *S3 Glacier 深度存檔* |  | 12小時 | 48小時 
|===
* *還原時間*：從標準儲存設備中的備份檔案還原資料所需的時間。此時間與不使用歸檔分層時直接從標準儲存設備執行的典型還原作業沒有差異。
+
有關 Amazon S3 Glacier 和 S3 Glacier Deep Archive 檢索選項的更多信息，請參閱 https://aws.amazon.com/s3/faqs/#Amazon_S3_Glacier["關於這些儲存類別的 Amazon 常見問題解答"^]。



--


[NOTE]
====
從歸檔儲存設備還原 Volume 或檔案可能需要額外時間。在備份與還原功能根據所選優先順序重試還原期間，作業監視器中該作業將保持「進行中」狀態。請在「作業監視器」中監視還原；當所有重試嘗試後，作業達到最終狀態（例如「已完成」或「失敗」）時，還原才會完成。除非作業最終失敗，否則請勿啟動另一次還原。
