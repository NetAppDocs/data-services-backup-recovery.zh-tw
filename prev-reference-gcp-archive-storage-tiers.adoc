[[supported-google-archival-storage-classes-for-netapp-backup-and-recovery]]
== NetApp Backup and Recovery支援的 Google 歸檔儲存類

備份檔案最初建立時，會儲存在 _Standard_ 儲存設備中。此分層針對儲存不經常存取的資料進行最佳化，但仍允許立即存取。

如果您的內部部署叢集使用 ONTAP 9.12.1 或更新版本，您可以在特定天數（通常超過 30 天）之後，於 NetApp Backup and Recovery 使用者介面中將較舊的備份分層至「歸檔」儲存設備，以進一步最佳化成本。此分層中的資料擷取成本較高，因此請考慮您可能需要從這些歸檔備份檔案還原資料的頻率。請參閱本頁關於從歸檔儲存設備還原資料的部分。

當您使用這種生命週期規則設定 NetApp Backup and Recovery 時，在您的 Google 帳戶中設定儲存桶時，請勿設定任何生命週期規則。

https://cloud.google.com/storage/docs/storage-classes["了解 Google 儲存類別"^]。



[[restore-data-from-archival-storage]]
== 從檔案儲存中復原數據

將較舊的備份檔案儲存在歸檔儲存設備中比儲存在標準儲存設備中便宜得多。但是，從歸檔儲存設備中的備份檔案還原資料需要更長的時間，而且成本更高。

從 Google Archive 恢復資料需要多少錢？:: 若要了解按地區劃分的 Google Cloud Storage 詳細定價，請造訪 https://cloud.google.com/storage/pricing["Google Cloud Storage 定價頁面"^]。
要恢復我在 Google Archive 中存檔的物件需要多長時間？:: 總還原時間分為兩部分：
+
--
* *檢索時間*：從存檔中檢索備份檔案並將其放置在標準儲存中的時間。這有時被稱為“補水”時間。與其他雲端供應商提供的「最冷」儲存解決方案不同，您的資料可以在幾毫秒內存取。
* *還原時間*：從標準儲存設備中的備份檔案還原資料所需的時間。此時間與不使用歸檔分層時直接從標準儲存設備還原的典型時間相同。


--


[NOTE]
====
從歸檔儲存設備還原 Volume 或檔案可能需要額外時間。在備份與還原功能根據所選優先順序重試還原期間，作業監視器中該作業將保持「進行中」狀態。請在「作業監視器」中監視還原；當所有重試嘗試後，作業達到最終狀態（例如「已完成」或「失敗」）時，還原才會完成。除非作業最終失敗，否則請勿啟動另一次還原。
