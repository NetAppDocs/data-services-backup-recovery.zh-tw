= 發現NetApp Backup and Recovery中的 KVM 工作負載
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
在 NetApp 備份與還原中探索 KVM 主機和虛擬機器，以便使用保護原則加以保護。在探索之前，您的 KVM 環境必須由管理平台（例如 Apache CloudStack）進行管理。

*必要的 NetApp Console 角色* Backup and Recovery 超級管理員。了解link:reference-roles.html["備份和恢復角色和權限"]。 https://docs.netapp.com/us-en/console-setup-admin/reference-iam-predefined-roles.html["了解所有服務的NetApp Console存取角色"^]。



[[add-a-management-platform-kvm-host-and-discover-resources]]
== 新增管理平台、KVM 主機並發現資源

新增管理平台和 KVM 主機訊息，讓NetApp Backup and Recovery發現工作負載。


NOTE: 將儲存系統新增至 NetApp Console 後，請等待幾分鐘再進行資源探索。如果在新增儲存系統後立即進行資源探索，可能會導致探索失敗。

.步驟
. 從NetApp Console選單中，選擇 *保護* > *備份和還原*。
. 在“工作負載”下，選擇“KVM”磁貼。
. 選擇*發現資源*。
. 輸入以下資訊：
+
.. *工作負載類型*：選擇*KVM*。
.. 如果您尚未將管理平台與備份和復原功能集成，請選擇「新增管理平台」。
+
... 輸入以下資訊：
+
**** *管理平台 IP 位址或 FQDN*：輸入管理平台的 IP 位址或 FQDN。
**** *API金鑰*：輸入用於驗證API請求的API金鑰。
**** *金鑰*：輸入用於驗證 API 請求的金鑰。
**** *連接埠*：輸入備份和還原與管理平台之間通訊所使用的連接埠。
**** *代理*：選擇一個控制台代理，用於促進備份和還原與管理平台之間的通訊。


... 完成後，選擇“新增”。


.. *KVM 設定*：請執行下列操作：
+
... 如果您尚未為此 KVM 主機儲存認證資料，請選擇 *新增認證資料*。
+
**** 選擇與該主機一起使用的控制台代理程式。
**** 輸入此憑證的名稱。
**** 輸入該帳戶的使用者名稱和密碼。
**** 選擇*完成*。


... 輸入下列資訊以新增 KVM 主機：
+
**** *KVM FQDN 或 IP 位址*：輸入主機的 FQDN 或 IP 位址。
**** *代理程式*：選擇用於 Backup and Recovery 與 KVM 主機之間通訊的 Console 代理程式。
**** *認證資料*：選擇已儲存的 KVM 主機認證資料。




.. *進階設定*：您可以選擇輸入與 KVM 主機通訊的連接埠，並從清單中選擇主機的管理平台。


. 選擇*發現*。
+

TIP: 此過程可能需要幾分鐘。



.結果
KVM 工作負載顯示在「庫存」頁面的工作負載清單中。



[[continue-to-the-netapp-backup-and-recovery-dashboard]]
== 繼續存取NetApp Backup and Recovery儀表板

.步驟
. 從NetApp Console選單中，選擇 *保護* > *備份和還原*。
. 選擇 KVM 工作負載磁貼。
. 從備份和還原選單中，選擇*儀表板*。
. 檢討資料保護的健康狀況。處於危險中或受保護的工作負載的數量會根據新發現、受保護和備份的工作負載而增加。
