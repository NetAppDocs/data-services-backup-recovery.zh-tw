[[configure-dns-for-air-gapped-host-discovery-in-netapp-console-local-deployment]]
== 在 NetApp Console 本機部署中設定 DNS 以實現氣隙主機探索

如果您在與網路隔離的環境中（資料庫主機無法透過標準 DNS 存取）使用 NetApp Console 本機部署，則必須暫時修改內部 RKE2 CoreDNS 組態。這可讓 Pod 將特定主機名稱解析為叢集內的 IP 位址，類似於在節點上新增 `/etc/hosts`項目。


IMPORTANT: 在進行任何變更之前，請檢查現有的 CoreDNS 組態，以避免置換任何現有的自訂設定。使用 RKE2 清單套用此變更，確保由 RKE2 營運者和執行階段一致地管理。

.開始之前
* 盡可能將 HelmChartConfig 檔案置於變更控制之下。
* 使用清晰的檔案名稱，以便明確 CoreDNS 置換的目的。
* 如果在 Corefile 中看不到預期的 DNS 記錄，請檢查 RKE2 伺服器日誌並確認清單檔案語法。


.步驟
. 檢查現有的 CoreDNS 組態，確保您沒有置換現有的變更：
+
[source, shell]
----
kubectl -n kube-system get cm rke2-coredns-rke2-coredns -o jsonpath='{.data.Corefile}'
----
. 複製以下命令區塊並編輯  `configBlock` 區域以新增您的靜態 DNS 記錄。這會在 RKE2 清單資料夾中建立一個 HelmChartConfig YAML 檔案，RKE2 會自動套用該檔案以置換 CoreDNS 組態：
+
[source, shell]
----
sudo tee /var/lib/rancher/rke2/server/manifests/rke2-coredns-config.yaml >/dev/null <<'YAML'
apiVersion: helm.cattle.io/v1
kind: HelmChartConfig
metadata:
  name: rke2-coredns
  namespace: kube-system
spec:
  # NOTE: This is a HelmChartConfig that *overlays* values onto the rke2-coredns
  # HelmChart already managed by RKE2. RKE2 watches /var/lib/rancher/rke2/server/manifests
  # and will re-render the rke2-coredns Helm release whenever this file changes.
  #
  # The `servers:` list below REPLACES the chart's default server definition,
  # so every plugin that was in the stock Corefile must be present here.
  # Do NOT delete plugins you don't recognize -- they are required for cluster DNS.
  valuesContent: |-
    servers:
    - zones:
      - zone: .
      port: 53
      plugins:
      - name: errors
      - name: health
        configBlock: |-
          lameduck 10s
      - name: ready
      - name: kubernetes
        parameters: cluster.local in-addr.arpa ip6.arpa
        configBlock: |-
          pods insecure
          fallthrough in-addr.arpa ip6.arpa
          ttl 30
      # ───────────────────────── EDIT BELOW ─────────────────────────
      # Static DNS records for hosts the corporate DNS cannot resolve.
      # Format:  <IP>  <FQDN>  [optional aliases...]
      # `fallthrough` MUST stay as the last line -- it lets every other
      # name go to the upstream resolver via the `forward` plugin below.
      - name: hosts
        configBlock: |-
          1.2.3.4 example.domain.com exampleshortname
          fallthrough
      # ───────────────────────── EDIT ABOVE ─────────────────────────
      - name: prometheus
        parameters: 0.0.0.0:9153
      - name: forward
        parameters: . /etc/resolv.conf
      - name: cache
        parameters: 30
      - name: loop
      - name: reload
      - name: loadbalance
YAML
sudo chmod 600 /var/lib/rancher/rke2/server/manifests/rke2-coredns-config.yaml
----
. 驗證 CoreDNS 是否已偵測到變更：
+
[source, shell]
----
kubectl -n kube-system get cm rke2-coredns-rke2-coredns -o jsonpath='{.data.Corefile}'
----
+
如果幾分鐘後變更仍未生效，請重新啟動 CoreDNS 部署，然後再次驗證 Corefile：

+
[source, shell]
----
kubectl -n kube-system rollout restart deploy/rke2-coredns-rke2-coredns
----
. 如果在探索資料庫主機後需要移除條目，請執行下列操作：
+
.. 從清單資料夾中刪除 HelmChartConfig 檔案。
.. 重新啟動 CoreDNS 部署：
+
[source, shell]
----
kubectl -n kube-system rollout restart deploy/rke2-coredns-rke2-coredns
----






[[discover-microsoft-sql-server-workloads-and-optionally-import-snapcenter-resources]]
== 發現 Microsoft SQL Server 工作負載並選擇性地匯入SnapCenter資源

在探索期間，NetApp 備份與還原會分析組織內各系統中的 Microsoft SQL Server 執行個體和資料庫。

此服務評估現有的保護層級，包括目前的備份原則、Snapshot 快照技術及備份與還原選項。

發現以下列方式發生：

* 如果您已有SnapCenter ，請使用NetApp Backup and Recovery and Recovery UI 將SnapCenter資源匯入NetApp Backup and Recovery and Recovery。
+

NOTE: 如果您已經擁有 SnapCenter，請先確認在從 SnapCenter 匯入之前已符合先決條件。例如，您應該先將內部部署的 SnapCenter 叢集儲存系統新增至 NetApp Console，然後再從 SnapCenter 匯入。請參閱link:concept-start-prereq-snapcenter-import.html["從SnapCenter匯入資源的先決條件"]。

* 如果您還沒有 SnapCenter，您仍然可以透過手動新增 vCenter 並執行探索來探索工作負載。




[[if-snapcenter-is-already-installed-import-snapcenter-resources-into-netapp-backup-and-recovery]]
=== 如果已安裝SnapCenter ，請將SnapCenter資源匯入NetApp Backup and Recovery

如果您已安裝SnapCenter ，請依照下列步驟將SnapCenter資源匯入NetApp Backup and Recovery 。  NetApp Console從SnapCenter發現資源、主機、憑證和計劃；您不必重新建立所有這些資訊。

您可以透過以下方式執行此操作：

* 在發現期間，選擇一個選項從SnapCenter匯入資源。
* 發現後，從「清單」頁面選擇一個選項來匯入SnapCenter資源。
* 發現後，從「設定」選單中選擇一個選項來匯入SnapCenter資源。有關詳細信息，請參閱link:br-start-configure.html["配置NetApp Backup and Recovery"]。


這是一個由兩個部分組成的過程：

* 匯入SnapCenter Server 應用程式和主機資源
* 管理選定的SnapCenter主機資源




==== 匯入SnapCenter Server 應用程式和主機資源

第一步從SnapCenter匯入主機資源，並在NetApp Backup and Recovery清單頁面中顯示這些資源。此時，資源尚未由NetApp Backup and Recovery管理。


TIP: 匯入SnapCenter主機資源後， NetApp Backup and Recovery不會自動接手保護管理。為此，您必須明確選擇在NetApp Backup and Recovery中管理匯入的資源。這可確保您已準備好透過NetApp Backup and Recovery備份這些資源。

.步驟
. 從NetApp Console左側導覽中，選擇 *保護* > *備份和還原*。
. 選擇*庫存*。
. 選擇*發現資源*。
. 從NetApp Backup and Recovery Discover 工作負載資源頁面中，選擇 *從SnapCenter匯入*。
. 輸入* SnapCenter應用程式憑證*：
+
.. * SnapCenter FQDN 或 IP 位址*：輸入SnapCenter應用程式本身的 FQDN 或 IP 位址。
.. *連接埠*：輸入SnapCenter伺服器的連接埠號碼。
.. *使用者名稱*和*密碼*：輸入SnapCenter伺服器的使用者名稱和密碼。
.. *控制台代理*：選擇SnapCenter的控制台代理程式。


. 輸入* SnapCenter伺服器主機憑證*：
+
.. *現有憑證*：如果選擇此選項，則可以使用已新增的現有憑證。選擇憑證名稱。
.. *新增憑證*：如果您沒有現有的SnapCenter主機憑證，則可以新增憑證。輸入憑證名稱、身份驗證模式、使用者名稱和密碼。


. 選擇“*導入*”來驗證您的條目並註冊SnapCenter伺服器。
+

NOTE: 如果 SnapCenter Server 已註冊，您可以更新現有的註冊資訊。



.結果
「清單」頁面顯示已匯入的 SnapCenter 資源，包括 Microsoft SQL Server 主機、執行個體和資料庫。

若要查看匯入的SnapCenter資源的詳細信息，請從「操作」功能表中選擇「查看詳細資料」選項。



==== 管理SnapCenter主機資源

匯入 SnapCenter 資源後，請在 NetApp Backup and Recovery 中管理主機資源。選擇管理後，NetApp Backup and Recovery 即可備份並還原匯入的資源。您無需再在 SnapCenter Server 中管理這些資源。

.步驟
. 匯入SnapCenter資源後，從備份和復原選單中選擇*Inventory*。
. 在「清單」頁面中，選取您要讓 NetApp Backup and Recovery 管理的已匯入 SnapCenter 主機。
. 選擇“操作”圖標image:../media/icon-action.png["操作選項"]> *查看詳情*顯示工作量詳情。
. 在清單 > 工作負載頁面中，選擇操作圖標image:../media/icon-action.png["操作選項"]> *管理* 顯示管理主機頁面。
. 選擇*管理*。
. 在管理主機頁面中，選擇使用現有 vCenter 或新增新的 vCenter。
. 選擇*管理*。
+
庫存頁面顯示新管理的SnapCenter資源。



您可以選擇從「操作」功能表中選擇「產生報表」選項來建立管理資源的報表。



==== 從清單頁面發現後匯入SnapCenter資源

如果您已經發現資源，則可以從清單頁面匯入SnapCenter資源。

.步驟
. 從控制台左側導覽中，選擇*保護*>*備份和還原*。
. 選擇*庫存*。
. 從庫存頁面中，選擇*匯入SnapCenter資源*。
. 請依照上面*匯入SnapCenter資源*部分中的步驟匯入SnapCenter資源。




[[if-you-dont-have-snapcenter-installed-add-a-vcenter-and-discover-resources]]
=== 如果您尚未安裝SnapCenter ，請新增 vCenter 並發現資源

如果尚未安裝 SnapCenter，您可以新增 vCenter 資訊並讓 NetApp Backup and Recovery 探索工作負載。在每個 Console 代理程式中，選擇要探索工作負載的系統。

如果您使用的是 VMware 環境，則此步驟為選用步驟。

.步驟
. 從控制台左側導覽中，選擇*保護*>*備份和還原*。
+
如果您是第一次登入備份和恢復，並且在控制台中有一個系統但沒有發現任何資源，則會顯示「歡迎使用新的NetApp備份和恢復」頁面，其中包含「發現資源」選項。

. 選擇*發現資源*。
. 輸入以下資訊：
+
.. *工作負載類型*：對於此版本，僅 Microsoft SQL Server 可用。
.. *vCenter 設定*：選擇現有的 vCenter 或新增新的 vCenter。若要新增新的 vCenter，請輸入 vCenter FQDN 或 IP 位址、使用者名稱、密碼、連接埠和協定。
+

TIP: 如果您要輸入 vCenter 資訊，請同時輸入 vCenter 設定和主機註冊的資訊。如果您在此處新增或輸入了 vCenter 資訊，接下來還需要在「進階設定」中新增外掛資訊。

.. *主機註冊*：選擇*新增憑證*並輸入包含您想要發現的工作負載的主機的資訊。
+

TIP: 如果要新增獨立伺服器而不是 vCenter 伺服器，則僅輸入主機資訊。



. 選擇*發現*。
+

TIP: 此過程可能需要幾分鐘。

. 繼續高級設定。




==== 在探索的過程中設定進階設定選項並安裝外掛

透過進階設定，您可以手動在所有已註冊的伺服器上安裝外掛代理程式。這樣，您可以將所有 SnapCenter 工作負載匯入 NetApp 備份與還原，以便在其中管理備份與還原。NetApp 備份與還原會顯示安裝外掛所需的步驟。

.步驟
. 從「探索資源」頁面，選擇右側的向下箭頭，繼續進入「進階設定」。
. 在發現工作負載資源頁面中，輸入以下資訊。
+
** *輸入外掛連接埠號碼*：輸入外掛使用的連接埠號碼。
** *安裝路徑*：輸入外掛的安裝路徑。


. 如果要手動安裝 SnapCenter 代理程式，請選擇以下選項：
+
** *使用手冊安裝*：選取此選項可手動安裝外掛。
** *新增叢集中的所有主機*：選擇此選項可在探索期間將叢集中的所有主機新增至 NetApp 備份與還原。
** *跳過選用的預安裝檢查*：選取此選項可跳過選用的預安裝檢查。例如，如果您知道記憶體容量或儲存空間考量在不久的將來將會變更，且您想立即安裝外掛，則可選取此選項。


. 選擇*發現*。




==== 繼續存取NetApp Backup and Recovery儀表板

. 從 NetApp Console 選單中，選取 *Protection* > *Backup and Recovery*。
. 選擇一個工作負載圖塊（例如，Microsoft SQL Server）。
. 從備份和還原選單中，選擇*儀表板*。
. 審查資料保護健全狀況。面臨風險或受到保護的工作負載數量會根據新探索、受到保護和備份的工作負載而增加。
+
link:br-use-dashboard.html["了解儀表板顯示的內容"]。
